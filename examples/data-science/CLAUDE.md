# Customer Churn Analysis

## Project

Machine learning project predicting customer churn for a SaaS product. Produces a weekly churn probability score for each customer, fed into the CRM for sales team outreach. Output: a trained XGBoost model, a scoring pipeline, and a Jupyter-based EDA report.

## Stack

- **Runtime**: Python 3.11 (managed by pyenv — see `.python-version`)
- **Environment**: conda (`environment.yml`) — not pip; conda handles non-Python deps
- **ML**: scikit-learn 1.4, XGBoost 2.0, pandas 2.2, numpy 1.26
- **Notebooks**: Jupyter Lab; notebooks live in `notebooks/`
- **Experiment tracking**: MLflow (local server or Databricks remote)
- **Testing**: pytest for pipeline code; notebooks are not unit-tested
- **Linting**: ruff (Python files only — not notebooks)

## Commands

```bash
conda env create -f environment.yml     # one-time environment creation
conda activate churn-analysis           # activate before anything else

jupyter lab                             # start Jupyter (notebooks/)
python src/train.py                     # train model, saves to models/
python src/score.py --input data/customers.parquet  # score customers
python src/evaluate.py                  # compute metrics on test split

pytest tests/                           # unit tests for pipeline code
ruff check src/                         # lint (src/ only, not notebooks)
mlflow ui                               # view experiment tracking UI (http://localhost:5000)
```

## Architecture

```
data/
  raw/          ← source data dumps — never edited, committed to DVC not git
  processed/    ← cleaned/feature-engineered data — generated by src/features.py
  external/     ← third-party reference data
notebooks/
  01-eda.ipynb           ← exploratory data analysis (run first)
  02-feature-eng.ipynb   ← feature engineering experiments
  03-model-selection.ipynb ← model comparison
src/
  features.py   ← feature engineering pipeline (production version of notebook logic)
  train.py      ← model training entry point
  score.py      ← batch scoring entry point
  evaluate.py   ← metrics computation
  utils.py      ← shared helpers
models/         ← trained model artifacts (.pkl, .json) — tracked by DVC
tests/
  test_features.py   ← unit tests for feature transformations
  test_scoring.py    ← unit tests for scoring pipeline
environment.yml     ← conda environment spec (source of truth for deps)
dvc.yaml            ← DVC pipeline definition
```

## Conventions

- **Think Before Coding**: state assumptions, ask when uncertain, never silently guess
- **Simplicity First**: minimum code that solves the problem; no speculative abstractions
- **Surgical Changes**: touch only what the task requires; don't improve adjacent code
- **Goal-Driven Execution**: convert vague requests into verifiable success criteria first
- **Notebook vs src/**: notebooks are for exploration only. Any logic that runs in production goes in `src/`. Notebooks should call `src/` functions, not reimplement them.
- **Numbered notebooks**: prefix notebooks with `01-`, `02-` etc. to communicate intended run order. Never rename existing notebooks (breaks DVC artifact refs).
- **Data via DVC**: never commit data files to git. Large files go through DVC: `dvc add data/raw/customers.parquet`. Run `dvc pull` to get data after cloning.
- **Random seeds**: always set `random_state=42` in sklearn and `np.random.seed(42)` in notebooks. Reproducibility is non-negotiable.
- **Experiment tracking**: log every training run to MLflow — at minimum: parameters, metrics, and the model artifact. Use `mlflow.autolog()` for sklearn/XGBoost.

## Environment

Copy `.env.example` to `.env`:
- `MLFLOW_TRACKING_URI` — `http://localhost:5000` for local; Databricks URI for remote tracking
- `DATA_PATH` — path to the raw data directory (defaults to `data/raw/` if unset)
- `MODEL_PATH` — path to save/load model artifacts (defaults to `models/`)

Database credentials (for pulling fresh customer data):
- `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` — get from 1Password → "Analytics DB (prod)"

## Gotchas

- **conda, not pip**: this project has non-Python deps (BLAS, libgomp for XGBoost). Installing with `pip install -r` instead of `conda env create` will fail in subtle ways — incorrect BLAS linking causes wrong numeric results, not crashes.
- **Activate the env first**: every command requires `conda activate churn-analysis`. If you see `ModuleNotFoundError: No module named 'xgboost'`, you forgot to activate.
- **DVC pull before running**: after cloning or after a teammate runs `dvc push`, run `dvc pull` to get the current data files. Running `python src/train.py` without data gives a confusing FileNotFoundError.
- **Notebooks are not the source of truth**: if a notebook and `src/features.py` disagree, `src/` is correct. Notebooks drift; `src/` is what runs in production.
- **Cell execution order matters**: notebooks are not idempotent. Always use "Restart Kernel & Run All" before sharing or committing a notebook — running cells out of order gives different results.
- **MLflow port conflict**: MLflow UI defaults to port 5000, which conflicts with AirPlay Receiver on macOS 12+. Run `mlflow ui --port 5001` if port 5000 is busy.
- **XGBoost GPU on M1/M2 Mac**: XGBoost GPU support requires the `libomp` conda package. If you see `XGBoostError: Cannot use GPU on Apple Silicon`, run `conda install -c conda-forge libomp`.
